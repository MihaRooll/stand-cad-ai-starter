# Начните отсюда

Этот архив — готовая основа репозитория для разработки стойки/корпуса с помощью ИИ в Cursor. В нём есть выбранный CAD-стек, настройки MCP, правила для агента, входные конфигурации, валидатор, тесты, план G0–G8, требования к передаче на производство и стартовый промпт для Opus 5.

Это **не готовый производственный чертёж конкретной стойки**. Реальную геометрию нельзя корректно начинать, пока не выбраны точные модели оборудования и не собраны размеры, массы, зоны открытия/обслуживания, тепло, кабели, режим эксплуатации и ограничения перевозки.

## Рекомендованный результат

- Cursor и Opus 5 управляют проектом.
- Параметрическая геометрия хранится как Python-код `build123d` и конфигурация в Git.
- `build123d-mcp` даёт ИИ возможность строить, отображать, измерять и проверять модель.
- STEP и PDF передают конструкцию выбранному производству.
- Производственный DXF для гнутого листа появляется только после DFM и подтверждения параметров гибки конкретным цехом.
- Сначала изготавливается один прототип; серийный релиз возможен только после его осмотра и испытаний.

## Запуск после распаковки

Откройте PowerShell в папке проекта:

```powershell
git init -b main
git add .
git commit -m "Initial AI-first CAD project specification"
```

Установите `uv`, если его ещё нет, затем закройте и снова откройте PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Запустите базовую проверку:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup_windows.ps1
```

Откройте эту папку в Cursor, перезапустите Cursor и проверьте, что сервер `build123d-mcp` отображается как подключённый. Конфигурация уже лежит в `.cursor/mcp.json`.

Скопируйте стартовый промпт:

```powershell
Get-Content .\OPUS_5_START_PROMPT.md -Raw | Set-Clipboard
```

Вставьте его в новый агентный диалог Cursor с Opus 5. Агент должен сначала прочитать репозиторий и пройти Gate G0, а не сразу рисовать корпус.

## Что потребуется от вас первым

Ответьте одним пакетом на вопросы из `docs/10_USER_INPUT_REQUIRED.md`. Минимум:

1. Точные модели и количество устройств в одной стойке.
2. Фото шильдиков, инструкции/ссылки и собственные измерения.
3. Габариты устройств в закрытом, рабочем и сервисном положении.
4. Масса, точки опоры, питание, тепло, вентиляция и выступающие разъёмы.
5. Как стойка работает, складывается, перемещается и загружается в транспорт.
6. Максимальные габариты/масса, двери, лифт, автомобиль, пороги и пол.
7. Бюджет прототипа, срок и требования к внешнему виду.

Не нужно осваивать CAD-интерфейс: ваша роль — подтверждать физические данные, рабочий сценарий и решения, влияющие на безопасность, цену и производство.

## Порядок чтения

1. `docs/13_REVIEW_AND_NEW_ANSWER_RU.md` — пересмотр исходного совета и новый ответ.
2. `OPUS_5_START_PROMPT.md` — контракт для реализации.
3. `AGENTS.md` — обязательные правила агента.
4. `docs/05_IMPLEMENTATION_PLAN.md` — план и контрольные ворота G0–G8.
5. `docs/10_USER_INPUT_REQUIRED.md` — единый список данных от пользователя.
6. `docs/06_MANUFACTURING_HANDOFF.md` — состав пакета для производства.
7. `reviews/` — три цикла проверки и финальный чек-лист архива.

## Главное ограничение

Красивый рендер, валидный STEP или прошедшие тесты не являются разрешением на изготовление. Для горячего, тяжёлого или мобильного оборудования нужны расчёты/испытания, проверка устойчивости и нагрузок, безопасная электрика, DFM выбранного производителя и физический прототип.
